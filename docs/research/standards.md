## 1. JDBC 4.3 (JSR 221) and its maintenance releases up to 2026: interfaces, semantics, type mapping, compliance, TCK

### Takeaway
JDBC is by far the largest surface (55 public types in `java.sql`, 19 in `javax.sql`, ~60 methods on `Connection`, ~56 on `Statement`, ~58 on `PreparedStatement`, ~121 on `CallableStatement`, ~195 on `ResultSet`, ~177 methods + 61 constants on `DatabaseMetaData`). Formal "JDBC Compliant" status requires full support of the API plus SQL-92 Entry Level and passing the compliance tests, which live inside the Java SE TCK (JCK) — obtainable only under Oracle's OCTLA for OpenJDK-derived work. Two maintenance releases after 4.3 matter for 2026: MR4/"JDBC 4.4" (Dec 2024, removes SecurityManager semantics) and MR5/"JDBC 4.5" (accepted 2025-12-09; adds `Types.JSON=2016`, `Types.DECFLOAT=2015`, AutoCloseable LOBs, `Connection.enquote*`, and a `{\\ ... \\}` escape/parameter-marker suppression syntax).

**Escape syntax (Chapter 13 of the spec, as implemented by Microsoft's JDBC driver)**

### Inferences
- A Rust library claiming "JDBC parity" cannot literally be JDBC-compliant (no Java, no JCK); the achievable claim is **feature parity with the JDBC 4.3 (+MR5) API surface**: connection lifecycle with auto-commit/isolation/savepoints/holdability, statement types (direct, prepared, callable with OUT params and REF CURSOR), result sets with forward-only + optional scrollable/updatable modes, multiple results + update counts (int and long), generated keys (by flag, column index, column name), batches with per-command status, warnings chain, timeouts (query vs network vs login), metadata (~25 catalog queries + ~150 capability probes), the escape syntax grammar incl. `{limit}` and the MR5 `{\\ … \\}` suppression, the type set in `java.sql.Types` incl. JSON/DECFLOAT, and the B-5/B-6 conversion matrices.
- Unverified recollection (JDBC 4.x spec §6.2/6.3): a compliant driver must fully implement `Driver`, `Connection`, `Statement`, `PreparedStatement`, `CallableStatement` (if the DBMS has stored procedures), `ResultSet`, `ResultSetMetaData`, `DatabaseMetaData`, `ParameterMetaData`, support `TYPE_FORWARD_ONLY`/`CONCUR_READ_ONLY`, the escape syntax, SQL-92 Entry Level plus DROP TABLE, and may use `SQLFeatureNotSupportedException` for optional features. - The MR4/MR5 churn shows the spec is still evolving (2024–2026): type codes 2015/2016 and the escape-suppression delimiters should be in the Rust design's "JDBC 4.5" column.

## 2. ODBC 3.8 / 4.0 (Microsoft) and ISO/IEC 9075-3 SQL/CLI: function groups, descriptors, conformance levels, type tables, SQLSTATE, diagnostics, driver loading

### Takeaway
ODBC 3.x is a C handle-based API (ENV/DBC/STMT/DESC) with ~76 functions (≈60 current + deprecated 2.x forms), four descriptors (APD/IPD/ARD/IRD) that underlie all binding, three interface-conformance levels (Core = ISO CLI + Open Group non-optional features; Level 1 adds transactions/scrollable cursors/procedures/multiple results; Level 2 adds three-part names, output params, bookmarks, bulk ops, statement-level async, timeouts, serializable isolation), a 5-char SQLSTATE model aligned to SQL-92/Open Group (`HY`=CLI-specific, `IM`=ODBC Driver-Manager-specific, `xxSxx`=ODBC subclasses), and ~175 `SQLGetInfo` info types. ODBC 3.8 added async connection ops, notification-based async, streamed output params, driver-aware pooling, `SQLCancelHandle`, `SQL_ATTR_RESET_CONNECTION`. Core conformance is explicitly "the features defined in the ISO CLI specification and the non-optional features of the Open Group CLI", which is the bridge to ISO 9075-3.

**Descriptors and binding**
- A descriptor describes either a set of dynamic parameters or a row; four kinds: Application Parameter Descriptor (APD, app's input/output argument buffers), Implementation Parameter Descriptor (IPD, same args after/before conversion), Application Row Descriptor (ARD, row as presented to the app), Implementation Row Descriptor (IRD, row as read from the DB). ### Inferences
- The ODBC "Core" list is the most precise public proxy for ISO 9075-3's mandatory routine set (the standard itself is paywalled); a Rust library claiming SQL/CLI parity should map each Core bullet to a trait method: handle lifecycle, bind-by-column, input parameter arrays, data-at-exec streaming, cursor naming, result-set metadata, four catalog queries (tables/columns/type info/statistics), connect/disconnect, prepare/execute/exec-direct, forward fetch, partial `GetData`, attribute get/set, descriptor fields, two diagnostic accessors, capability discovery (`GetFunctions`/`GetInfo`/`NativeSql`), commit, cancel, best-row-id.
- The three-level model is a usable template for a Rust "conformance profile" (Core / Level 1 / Level 2) with the same feature numbers 101–109 and 201–211, so an ODBC bridge can report `SQL_ODBC_INTERFACE_CONFORMANCE` honestly.
- ODBC's descriptor model (APD/IPD/ARD/IRD + row-wise/column-wise binding + status arrays) is the closest classical analogue to Arrow-style columnar buffers; a Rust design can treat ARD/APD as "application buffer layout" and IRD/IPD as "server-described schema", which is exactly the split ADBC makes with Arrow schemas.
- Being loadable by the Windows DM/unixODBC requires a C ABI shared library exporting the ODBC function names (at minimum the Core set, with `SQLGetFunctions` reporting the rest), registry/odbcinst.ini entries with `APILevel`, `ConnectFunctions`, `DriverODBCVer`="03.80", `SQLLevel`, and optionally a setup DLL exporting `ConfigDSN/ConfigDriver` (the installer-DLL function list was not opened; unverified).

### Gaps
- ISO/IEC 9075-3:2023 text (routine list, conformance clauses, return codes, diagnostics area, multi-row fetch) could not be opened (paid; iso.org and iTeh pages blocked the fetcher). Clause numbers for SQL/CLI could not be cited.
- The exact unixODBC/iODBC driver-loading contract (which symbols are resolved via `dlsym`, ANSI vs `W` entry points, `SQLGetFunctions` fallback) was not found in an opened document.
- ODBC 4.0 draft has no version/date statement; its status as a non-shipping draft is inferred from the empty Releases page and absence of a 4.0 Driver Manager.

## 3. ADBC (Apache Arrow Database Connectivity) 1.0 / 1.1: C API, driver manager, bindings, drivers, transport difference

### Takeaway
ADBC is a small, columnar, ABI-stable C API (`adbc.h` is canonical): three objects (`AdbcDatabase`, `AdbcConnection`, `AdbcStatement`) + `AdbcError`/`AdbcPartitions`, 15 status codes, a `struct AdbcDriver` function table (26 entries in 1.0.0, +31 in 1.1.0), string/typed options instead of hundreds of attribute enums, Arrow `ArrowArrayStream` for all results and parameter binding, bulk ingest as a first-class operation, partitioned/incremental execution, and a driver manager that loads drivers by shared library + `AdbcDriverInitFunc` with version negotiation. Metadata (`GetInfo`, `GetObjects`, `GetTableSchema`, `GetTableTypes`, `GetStatistics`) is returned as Arrow data with fixed schemas, not as ~170 scalar probes. Libraries are at ADBC 24 (lib 1.12.0, July 2026; API spec still 1.1.0), with ADBC 25 (1.13.0, Oct 2026) reported by third parties.

### Inferences
- Transport is the structural difference: JDBC/ODBC/DB-API move data row-at-a-time through typed getters or bound C buffers; ADBC moves whole Arrow record batches through `ArrowArrayStream`, so "parity with ADBC" for a Rust library means exposing results and parameters as `arrow::RecordBatch` streams, supporting bulk ingest, partitions, Substrait plans, and the fixed metadata schemas — not implementing getters.
- ADBC's error model (status + message + vendor code + SQLSTATE + key/value details) is a superset of JDBC's `SQLException` and ODBC's diagnostic record; a Rust `Error` type that carries exactly these five fields can be mapped losslessly to all three.
- The driver-manager + manifest model is the modern replacement for ODBCINST.INI; a Rust library wanting ADBC loadability must either export the C ABI (`adbc_core::ffi`/`export_driver!` exists in the crate per general knowledge — the fetched page did not show it) or publish a manifest.

### Gaps
- The feature-support matrix per driver (bulk ingest, partitions, transactions, cancellation, statistics…) was removed/moved; `driver/status.html` returned empty and the old `status.rst` 404s.
- Official ADBC 25 announcement not found (only third-party posts).
- The `adbc_core` trait method lists and the `ffi`/`export_driver!` facility were not visible on the crate front page.

## 4. R2DBC 1.0.0 (reactive): SPI surface, transactions, back-pressure, TCK

### Takeaway
R2DBC 1.0.0.RELEASE (final 2022-04-25, Reactive Foundation) is a deliberately minimal, non-blocking SPI on Reactive Streams: `ConnectionFactory → Connection → Statement/Batch → Result → Row/RowMetadata`, every operation deferred until subscription and cancellable, 0-based indexes, bind by index or name, `Result.Segment` streams (rows, update counts, messages, OUT parameters), extensible `IsolationLevel`/`TransactionDefinition`, `R2dbcException` with SQLState + vendor code and transient/non-transient subclasses, a URL scheme `r2dbc[s]:driver[:protocol]://[user:password@]host[:port][/path][?options]`, and a JUnit-5 TCK (`io.r2dbc.spi.test.TestKit`) that drivers extend.

### Inferences
- R2DBC is the closest template for an async Rust API: `Publisher` ≈ `Stream`/`AsyncIterator`, cancellation-releases-resources ≈ `Drop` on a stream, `Result.Segment` ≈ an enum of `Row | UpdateCount | Message | OutParameters`, `fetchSize` as a hint plus back-pressure (`demand`) as the real flow control.

## 5. Other language-level APIs (PEP 249, Go database/sql, ADO.NET, Arrow Flight SQL): where they converge and diverge

### Takeaway
All surveyed APIs share a four-layer core — connection factory/registry, connection with transaction control, statement with parameters, forward-only result iteration with per-column typed access plus column metadata — and all expose update counts, generated keys (in some form), NULL handling, and a SQLState/vendor-code error. They diverge on: placeholder syntax (JDBC/ODBC `?` only; DB-API five styles; Go driver-defined; R2DBC index or name), index base (JDBC/ODBC 1-based, R2DBC/ADO.NET/Go/ADBC 0-based), cursor models (ODBC/JDBC scrollable+updatable; all others forward-only), metadata (ODBC/JDBC ~170 probes; ADO.NET `GetSchema` collections; Flight SQL `SqlInfo` IDs; ADBC Arrow tables; Go/DB-API/R2DBC almost none), batching (ODBC param arrays; JDBC `addBatch`; ADO.NET `DbBatch`; DB-API `executemany`; ADBC bulk ingest), async (R2DBC/ADO.NET/Go contexts native; ODBC 3.8 polling/notification; JDBC none), and transport (Arrow columnar in ADBC/Flight SQL vs row-oriented everywhere else).

- **Common core present in every API**: open connection from a string/options; begin/commit/rollback + auto-commit default; isolation level selection (JDBC 4 levels + NONE; ODBC bitmask; ADBC 7 incl. snapshot/linearizable; Go 8 incl. - Index base and placeholder style are the two most common sources of bridge bugs: a Rust core API should pick one (0-based, `?` or `$n`) and document the translation for each bridge.

## 6. SQL standard type system and SQLSTATE (ISO/IEC 9075-2:2023) and how JDBC/ODBC map them

### Takeaway
ISO/IEC 9075-2:2023 (SQL/Foundation, 6th ed., June 2023, ~1715 pp.) is paywalled; its predefined-type rules are inherited largely unchanged from SQL-92 §4.2–4.6 (character, bit, exact/approximate numerics with precision/scale, DATE/TIME/TIMESTAMP with optional fractional-seconds precision and WITH TIME ZONE, year-month and day-time INTERVAL classes with leading-field precision) plus later additions (BOOLEAN, BIGINT, BLOB/CLOB, ARRAY/MULTISET, ROW, XML, and in SQL:2023 the JSON type T801/T802/T803). SQLSTATE is a 5-char class+subclass code whose standard classes (00, 01, 02, 07, 08, 0A, 22, 23, 24, 25, 28, 40, 42, HY, …) are shared verbatim by ODBC, JDBC's exception subclasses, ADBC's `sqlstate[5]`, R2DBC's `getSqlState()`, and PostgreSQL's error codes; vendors add classes/subclasses from the implementation-defined ranges (`S`-subclasses in ODBC, `P`-subclasses in PostgreSQL).

### Cited Findings
- ISO/IEC 9075-2:2023 Foundation: Edition 6, approved/published 2023-06-01, ~1715 pages (BSI lists 1740), ISO/IEC JTC 1/SC 32. — search summary over [iTeh](https://standards.iteh.ai/catalog/standards/iso/1956ec63-3f5b-496d-8173-64a2ce5ef2b3/iso-iec-9075-2-2023), [SCC](https://scc-ccn.ca/standardsdb/standards/8185304), [GlobalSpec](https://reference.globalspec.com/ref/14640285/iso-iec-9075-2-2023) [checked 2026-11-09]

### Inferences
- A Rust type enum that covers the union of ODBC SQL type identifiers (incl. 13 intervals, GUID, W-types), JDBC `Types` (incl. BOOLEAN, ROWID, N-types, XML, REF_CURSOR, TZ types, DECFLOAT, JSON) and Arrow logical types (needed for ADBC/Flight SQL) is the minimal "type parity" set; the standard's own list (character/binary strings, exact/approximate numerics, boolean, datetime with/without zone, intervals, LOBs, ARRAY/MULTISET/ROW, XML, JSON) is a strict subset of that union.
- SQLSTATE should be stored as a `[u8; 5]` (not an enum) with helper classification into warning/no-data/error and the eight JDBC-style categories, since every surveyed API accepts vendor-defined classes.

### Gaps
- No clause numbers from 9075-2:2023 could be cited (document not opened); the predefined-type list above is reconstructed from SQL-92 §4 plus later-edition feature IDs.
- Whether SQL:2023 kept DECFLOAT (SQL:2016 feature T076 in some drafts; JDBC MR5 adds it) was not confirmed from a primary source.

## 7. Connection URL / connection-string conventions (JDBC, ODBC, R2DBC, ADBC, libpq, MySQL) — basis for one compatible Rust URL scheme

### Takeaway
Two families exist: **URI-shaped** (`jdbc:subprotocol:subname`, `r2dbc[s]:driver[:protocol]://user:pw@host:port/db?k=v`, `postgresql://…`, `mysql[x]://…`, ADBC `uri` option) and **keyword=value;** strings (ODBC `DSN=…;DRIVER={…};UID=;PWD=;`, libpq `host=… port=…`, ADO.NET connection strings). Shared conventions: percent-encoding for reserved chars, multi-host lists for failover, `?`/`&` query options, case-insensitive keywords, and a driver/scheme token that selects the implementation. Differences that a unified scheme must absorb: first-wins (ODBC) vs last-wins (libpq `PQconnectdbParams`) duplicate-key rules, case-sensitive keys (Connector/J) vs case-insensitive (ODBC, MySQL X), JDBC's lack of `//` for some drivers, and per-host property sublists (Connector/J).

### Cited Findings
- JDBC: `jdbc:subprotocol:subname`; `DriverManager` passes the URL to each driver's `acceptsURL`/`connect`; precedence between URL-embedded and `Properties` values is implementation-defined. — DriverManager/Driver javadoc (§1).
- PgJDBC: `jdbc:postgresql:database`, `jdbc:postgresql://`, `jdbc:postgresql://host/database`, `jdbc:postgresql://host/`, `jdbc:postgresql://host:port/database`, `jdbc:postgresql://host:port/`, multi-host `jdbc:postgresql://host1:port1,host2:port2/database`; default host localhost, port 5432, database defaults to user name; IPv6 in brackets, reserved chars percent-encoded; ~60 parameters (`user, password, options, ssl, sslmode, sslcert, sslkey, sslrootcert, sslhostnameverifier, loginTimeout, connectTimeout, socketTimeout, cancelSignalTimeout, tcpKeepAlive, autosave, binaryTransfer, prepareThreshold, preparedStatementCacheQueries/SizeMiB, preferQueryMode, defaultRowFetchSize, maxResultBuffer, adaptiveFetch, reWriteBatchedInserts, escapeSyntaxCallMode, stringtype, ApplicationName, readOnly, currentSchema, targetServerType, hostRecheckSeconds, loadBalanceHosts, socketFactory, replication, channelBinding, gssEncMode, …`). — [PgJDBC connecting](https://jdbc.postgresql.org/documentation/use/) [checked 2026-11-09]
- MySQL Connector/J: `protocol//[hosts][/database][?properties]`; protocols `jdbc:mysql:`, `jdbc:mysql:loadbalance:`, `jdbc:mysql:replication:`, `mysqlx:`, `jdbc:mysql+srv:` (+loadbalance/replication), `mysqlx+srv:`; hosts as `host:port`, `address=(host=h)(port=p)(k=v)`, `(host=h,port=p,k=v)`, comma lists, bracketed sublists sharing credentials `user:pw@[h1:p1,h2:p2]`; defaults localhost, 3306 (classic)/33060 (X); properties after `?` joined by `&`, keys case-sensitive, per-host values override global, leftmost credentials win. — [Connector/J URL syntax](https://dev.mysql.com/doc/connector-j/en/connector-j-reference-jdbc-url-format.html) [checked 2026-11-09]
- MySQL URI-like strings (X DevAPI / Shell): `[scheme://][user[:[password]]@]host[:port][/schema][?attr=value&…]`, "similar to but not identical to" RFC 3986; schemes `mysqlx://`, `mysql://`, `mysqlx+srv://`; IPv6 in brackets; Unix socket via percent-encoding or parentheses `(/path/to/socket.sock)`; key-value form `{user:'u', host:'h', port:33065}`; options `ssl-mode (DISABLED, PREFERRED default, REQUIRED, VERIFY_CA, VERIFY_IDENTITY)`, `ssl-ca/capath/cert/key/crl/crlpath`, `tls-version(s)`, `auth-method (AUTO, MYSQL41, SHA256_MEMORY, PLAIN, …)`, `connect-timeout`, `compression`, `connection-attributes`; parameters case-insensitive, each at most once. — [MySQL URI-like connection strings](https://dev.mysql.com/doc/refman/8.4/en/connecting-using-uri-or-key-value-pairs.html) [checked 2026-11-09]
- libpq: keyword/value form `host=localhost port=5432 dbname=mydb connect_timeout=10` (single quotes for empty/space values, backslash escapes) and URI form `postgresql://[userspec@][hostspec][/dbname][?paramspec]` (`postgres://` also), every part optional; multi-host `host1:123,host2:456` with matching `port` lists; percent-encoding (RFC 3986); Unix socket via `?host=/var/lib/postgresql` or `%2Fvar%2Flib%2Fpostgresql`; `ssl=true` translated to `sslmode=require` for JDBC compatibility; ~55 keywords incl. `host, hostaddr, port, dbname, user, password, passfile, require_auth, channel_binding, connect_timeout, client_encoding, options, application_name, fallback_application_name, keepalives*, tcp_user_timeout, replication, gssencmode, sslmode (disable, allow, prefer, require, verify-ca, verify-full), sslnegotiation, sslcert, sslkey, sslpassword, sslrootcert (system), sslcrl(dir), sslsni, requirepeer, ssl_min/max_protocol_version, min/max_protocol_version, krbsrvname, gsslib, gssdelegation, service, target_session_attrs (any, read-write, read-only, primary, standby, prefer-standby), load_balance_hosts, oauth_*, scram_*`; `PQconnectdbParams` last non-empty value wins; env fallback (`PGHOST, PGPORT, PGDATABASE, PGUSER, PGPASSWORD, …`, listed in §32.15, not on the fetched page). — [libpq connection strings](https://www.postgresql.org/docs/current/libpq-connect.html) [checked 2026-11-09]
- ODBC `SQLDriverConnect` connection string: `attribute[;attribute…]`, `keyword=value`, `DRIVER=[{]value[}]`, keywords `DSN, FILEDSN, DRIVER, UID, PWD, SAVEFILE` + driver-defined; keywords case-insensitive, values may be case-sensitive; first occurrence of a repeated keyword wins; `DSN` vs `DRIVER` — whichever appears first; `FILEDSN`/`DSN` mutually exclusive; braces required around values containing `;`; avoid `[]{}(),;?*=!@` unbraced and backslash in keywords/DSN names; DSN length ≤ `SQL_MAX_DSN_LENGTH`, driver name ≤ 255. — [SQLDriverConnect](https://learn.microsoft.com/en-us/sql/odbc/reference/syntax/sqldriverconnect-function) [checked 2026-11-09]
- R2DBC: `r2dbc:driver[:protocol]://[user:password@]host[:port][/path][?option=value]`, `r2dbcs:` for SSL, fragment reserved; standard option literal names `driver, protocol, host, port, user, password, database, connectTimeout, ssl, lockWaitTimeout, statementTimeout`. — R2DBC spec (§4).
- ADBC: canonical database options `uri`, `username`, `password` (1.1); when no `driver` option is given the driver manager uses the URI scheme as the driver name and passes the full URI to the driver. — adbc.h and driver_manifests pages (§3).
- ADO.NET: `DbConnection.ConnectionString` with `DbConnectionStringBuilder` base class for strongly typed `key=value;` builders. — System.Data.Common (§5).

### Inferences
- A Rust scheme of the form `karez:<driver>[+<protocol>]://[user[:password]@]host1[:port1][,host2[:port2]]/[database][?key=value&…]` can round-trip to all URI-shaped families (strip the `rdbc:` prefix and remap the driver token to `jdbc:`/`r2dbc:`/`postgresql:`/`mysql:`), and can be lowered to ODBC/libpq keyword strings by a per-driver keyword table (`user→UID/user`, `password→PWD/password`, `database→DATABASE/dbname`, `host→SERVER/host`, `port→PORT/port`, `sslmode→Encrypt/sslmode`).
- The scheme must define: percent-encoding per RFC 3986, IPv6 brackets, Unix-socket host via percent-encoded path or a dedicated `socket=` key, duplicate-key policy (recommend "last wins" like libpq and reject conflicting case variants like Connector/J), and a `driver=` override like ADBC/R2DBC for name-vs-scheme mismatches.

### Gaps
- Oracle thin (`jdbc:oracle:thin:@//host:port/service`) and SQL Server (`jdbc:sqlserver://host:port;databaseName=…;` semicolon-property style) URL grammars were not opened; they are notable because they mix URI and `key=value;` styles.
- libpq environment variable list (§32.15) and MySQL Windows named-pipe URI form were not on the fetched pages.

## 8. What "feature parity with the standard" should mean for an idiomatic Rust RDBC (synthesis for the checklist)

### Takeaway
Parity should be declared per standard and per level, not as a single boolean: (a) **JDBC 4.3/4.5 surface parity** (the largest checklist), (b) **ODBC Core / Level 1 / Level 2 feature parity** using Microsoft's numbered features 101–109 and 201–211, (c) **ADBC 1.1.0 function-table parity** (57 driver entry points + option keys + fixed metadata schemas), (d) **R2DBC 1.0 TCK parity** (the ~35 TestKit scenarios), plus a common type/SQLSTATE/URL layer. The bridges (an ODBC driver DLL/.so, an ADBC C driver, a JDBC/R2DBC adapter) then only translate names and index bases.

### Cited Findings
- The normative compliance statements that exist publicly: JDBC — `jdbcCompliant()` requires full JDBC API support + SQL-92 Entry Level + passing compliance tests (§1); ODBC — "ODBC Drivers must implement the functions in the Core interface conformance level", Core = ISO CLI + Open Group non-optional features, Level 1/2 features enumerated (§2); ADBC — a driver must implement each ADBC function, export each standard name, and provide an init function filling the versioned `AdbcDriver` table, returning `ADBC_STATUS_NOT_IMPLEMENTED` for unsupported functions/versions (§3); R2DBC — Chapter 4 requires transactions, bind markers, zero-based indexes, ServiceLoader discovery, and the TCK (§4).

### Inferences (checklist skeleton derived from the sources above)
1. **Connection layer**: open from URL/options (§7); `isValid`/`validate(LOCAL|REMOTE)`/`Ping`; `abort`; network timeout vs login timeout vs statement timeout (JDBC `setNetworkTimeout`/`DriverManager.setLoginTimeout`/`setQueryTimeout`; ODBC `SQL_ATTR_CONNECTION_TIMEOUT`/`LOGIN_TIMEOUT`/`QUERY_TIMEOUT`; R2DBC `connectTimeout`/`statementTimeout`/`lockWaitTimeout`); client info (`ApplicationName`, `ClientUser`, `ClientHostname`); catalog/schema switching (`setCatalog/setSchema`, `SQL_ATTR_CURRENT_CATALOG`, ADBC `adbc.connection.catalog/db_schema`); read-only mode; pool hooks (`beginRequest/endRequest`, `SQL_ATTR_RESET_CONNECTION`, R2DBC `Lifecycle`, Go `SessionResetter`).
2. **Transactions**: auto-commit default on; begin/commit/rollback; isolation levels = union {NONE, READ_UNCOMMITTED, READ_COMMITTED, WRITE_COMMITTED (Go), REPEATABLE_READ, SNAPSHOT (ADBC/Go), SERIALIZABLE, LINEARIZABLE (ADBC/Go)}; savepoints (named/unnamed, release); `TransactionDefinition`-style attributes (read-only, name, lock wait); capability flags (`supportsTransactions`, `SQL_TXN_CAPABLE` DML/DDL semantics, `dataDefinitionCausesTransactionCommit`); XA/2PC optional.
3. **Statements**: direct execute (any statement, multiple results), prepared (positional `?`/`$n`, named `:name` optional), callable (IN/OUT/INOUT, return value, REF CURSOR), batch (per-command status incl. `SUCCESS_NO_INFO`/`EXECUTE_FAILED`, large counts), parameter arrays (ODBC `PARAMSET_SIZE` semantics, `SQL_PARAM_ARRAY_ROW_COUNTS`), generated keys (flag / column indexes / column names), max rows/field size, fetch size/direction hints, escape processing on/off plus the JDBC 4.5 `{\\ … \\}` suppression, `nativeSQL`, cancel from another thread, poolable/closeOnCompletion hints, parameter metadata (count, mode, type, precision, scale, nullability, class name).
4. **Results**: forward-only streaming (default); optional scroll-insensitive/sensitive, updatable, holdability over commit, bookmarks (ODBC L2); row-at-a-time typed access with the B-6 conversion matrix; columnar access as Arrow batches (ADBC parity); LOB streaming in chunks (`getBytes(offset)`, `SQLGetData`, `GetStream`); `wasNull`; warnings chain; column metadata (name, label, type code, type name, precision, scale, nullability, signed, auto-increment, case-sensitive, searchable, read-only/writable, table/schema/catalog, Java/Rust class name); multiple result sets with update counts interleaved.
5. **Metadata**: the 25 JDBC catalog queries / 11 ODBC catalog functions / ADBC `GetObjects` depth levels and `GetTableSchema`/`GetTableTypes`/`GetStatistics` / Flight SQL `CommandGet*` as one Rust `Catalog` API returning tables (ideally Arrow) with the JDBC/ODBC column layouts; a capability map covering `SQLGetInfo`'s ~175 info types and `DatabaseMetaData`'s ~150 `supports*/getMax*` methods, with `SQL_SQL_CONFORMANCE`/`supportsANSI92*` and interface-conformance level reporting.
6. **Types**: enum = union of ODBC SQL type ids (incl. 13 intervals, GUID, W-types) + `java.sql.Types` (incl. ROWID, N-types, SQLXML, REF_CURSOR, TZ types, DECFLOAT=2015, JSON=2016) + Arrow logical types; conversion tables B-1…B-6 and ODBC Appendix D as the normative conversion matrix; `SQL_NUMERIC_STRUCT`-style exact decimals; nanosecond timestamps (ODBC fraction = ns; JDBC `Timestamp` ns); time zones via offset types.
7. **Errors**: `{message, sqlstate: [u8;5] | None, vendor_code: i32, status: AdbcStatusCode-like, details: Vec<(key, bytes)>, cause, next}` with classification into JDBC's transient/non-transient families and ODBC's warning/no-data/error ranking; diagnostic record extras (row/column number, server/connection name, dynamic function).
8. **Loading/bridging**: C ABI exports for ODBC (Core function set, `03.80`, registry/odbcinst.ini keys) and ADBC (`AdbcDriverInit`, versioned table, TOML manifest); R2DBC/JDBC adapters via JNI/FFI are out of scope for a pure-Rust core but their URL/option names should be accepted.
9. **Async**: R2DBC-style demand-driven streams with cancellation-releases-resources semantics; ODBC 3.8 async maps to Rust futures with `SQL_STILL_EXECUTING` ≈ `Poll::Pending`.

### Gaps
- None of the standards defines a numeric "percentage of parity"; the above is a synthesis. The two missing primary texts (JDBC 4.3 Ch. 6 and ISO 9075-3:2023) should be acquired before the checklist is frozen.
